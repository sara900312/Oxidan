## الخطة العامة

الطلب ضخم ويمس قاعدة البيانات، الواجهة، الذكاء الاصطناعي، والصلاحيات. لتفادي كسر النظام سأنفذه على **4 دفعات مستقلة**، كل دفعة قابلة للاختبار قبل الانتقال للتي بعدها. جميع التغييرات backward compatible ولا تحذف بيانات.

---

### الدفعة 1 — لوحة التحكم (Dashboard)

**قاعدة البيانات**
- جدول جديد `dashboard_snapshots(user_id, snapshot_date, total, high, analyzed, won)` مع RLS + PK مركب لمنع التكرار.
- Cron يومي (`pg_cron` + `pg_net`) يستدعي endpoint عام `/api/public/hooks/snapshot-dashboard` لالتقاط snapshot لكل مستخدم.

**الواجهة**
- بطاقات KPI بمؤشر مقارنة (`+8 هذا الأسبوع` / `+5 منذ أمس`) محسوب من آخر snapshot قبل 7 أيام و24 ساعة.
- بطاقة "الصفقات الرابحة" تصبح Link → `/companies?stage=won`.
- Empty state لكل بطاقة تحوي 0: رسالة إرشادية بدلاً من الرقم.
- قائمة الأولوية القصوى: قائمة sort dropdown (القطاع، المدينة، الأولوية، آخر تحليل، درجة الفرصة) + skeleton loading أثناء الجلب.
- الحفاظ الكامل على الهوية البصرية الحالية (glass-card, gold).

---

### الدفعة 2 — صفحة الشركات

- إعادة ترتيب أزرار الهيدر: `إضافة شركة` + `التحليل الجماعي` ظاهرة، وقائمة `المزيد ▾` (استيراد / تصدير Excel / CSV).
- Tooltip + زر "عرض المزيد" لوصف الشركة بدلاً من قص النص.
- فرز حقيقي حسب `priority_score` (وليس فقط الفئة اللونية).
- Legend للألوان (🟢 منخفضة / 🟠 متوسطة / 🔴 عالية) بجانب الجدول.
- Backend Search: تحديث `listCompanies()` في `src/lib/companies.ts` ليستخدم Supabase `.or()` للبحث في الاسم/القطاع/المدينة/الدولة/البريد/الهاتف/الوصف مع debounce.
- Skeleton loading أثناء البحث.

---

### الدفعة 3 — صفحة تفاصيل الشركة + صفحة التحليل

**تفاصيل الشركة**
- استبدال `—` بـ `غير معروف · 🔍 ابحث الآن`. الزر يستدعي server function جديد `enrichField(companyId, field)` يبحث بالذكاء الاصطناعي لهذا الحقل فقط ويحدّث DB.
- تنظيم الحقول إلى مجموعات: معلومات التواصل / السوشيال ميديا / النضج الرقمي / الموقع الإلكتروني / معلومات عامة.
- حالة الموقع (`website_status`: يعمل/قريباً/متوقف/غير معروف) عمود جديد + عرض منفصل عن الرابط.
- خرائط Google: العنوان نفسه clickable إذا وجد رابط، وإخفاء الرابط الطويل.
- ترجمة تلقائية: إذا حُدد العرض بالعربية و`report` يحتوي نصاً إنجليزياً، يُرسل إلى AI للترجمة (مع cache بـ `report.translated_ar` داخل نفس السجل) بحيث لا يتكرر الاستهلاك. ينفذ فوريّاً لجميع التقارير القديمة عند فتحها.

**صفحة التحليل**
- "لماذا هذا الترتيب؟" يعرض قائمة عوامل بالوزن (+20 موقع غير مكتمل / -5 معلومات ناقصة...) من `report.priority_factors[]`. يتطلب تحديث الـ prompt.
- تبويبات نظيفة بدون تكرار: Overview (حقول DB) / Report (تقرير AI) / Files / Timeline.
- **Audit Trail حقيقي**: جدول `analysis_audit(company_id, actor_user_id, version, changes_json, created_at)` + عرضه في تبويب History.
- إعادة تسمية الأزرار: `⚡ تحديث سريع` (delta) و `🧠 تحليل شامل` (full).
- عرض `آخر تحديث: قبل 3 أيام` بجانب الزر.

### الدفعة 4 — Pipeline + الإعدادات + الترجمة الشاملة

**Pipeline**
- الاعتماد على العمود الحالي `stage`. Drag & Drop موجود؛ سنغني الكروت بـ (آخر تواصل، المسؤول، الأولوية، درجة الفرصة).
- Trigger DB: عندما `priority = 'high'` وتحدث `stage` من `new_lead` أو `researching` → ينقل تلقائياً إلى `contact_ready`.
- ترحيل: كل شركة بدون `stage` → `new_lead`.

**الصلاحيات**
- استخدام `user_roles` الموجود (`admin`, `sales`, `marketing`, `user`).
- سياسات RLS محدّثة: `admin` يرى الكل، `sales`/`marketing` يرى `created_by = auth.uid() OR assigned_to = auth.uid()` فقط.
- شاشة الإعدادات: قسم الأدوار (Admin فقط) لتعيين الأدوار للمستخدمين.

**الترجمة الشاملة**
- مراجعة كل النصوص الإنجليزية المتبقية في الواجهة ونقلها إلى قاموس `i18n.tsx`.
- **ترجمة التقارير القديمة**: عند فتح تقرير قديم بالعربية، إذا لم يوجد `translated_ar`، ينفذ استدعاء AI مرة واحدة ويحفظ الترجمة داخل نفس السجل (`report.translated_ar = {...}`) — استهلاك credits لمرة واحدة فقط لكل تقرير.
